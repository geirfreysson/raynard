Raynard System map Tauri v2 · Pi agent runtime

Agent architecture

From question to data — and from intent to code.

Raynard uses two separate Pi agents. The main agent researches and routes. The coding agent edits plugins. They start at different moments, use different models, and never share write access.

One host, two Pi agents, two sharply scoped jobs.

Important Selecting Build mode does not itself start the coding Pi. It starts only after the request is resolved, the user confirms writing code, and a plugin directory exists—or immediately on a follow-up when that chat already has an active plugin.
01

Pi is process-scoped

Each agent lives in a Node sidecar created for one stream. Rust owns its process ID, forwards events, and terminates it on Stop.

02

Tools are native, not textual

Generated plugin schemas become native Pi tools. There is no regex intent router and no Markdown pseudo-tool protocol in the live chat path.

03

Models have separate roles

The Chat / Explore model drives the main Pi. The Coding / Build model drives the coding Pi. The /models flow configures them independently.
